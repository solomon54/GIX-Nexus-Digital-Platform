# Documentation Principles

These carry forward from the original Master Specification governance model and apply
project-wide, regardless of which folder a document lives in.

1. **Source fidelity.** Every company fact traces to `01_SOURCE_BASELINE/frozen/`.
   No invented clients, metrics, certifications, or headcounts.
2. **Classification discipline.** Every non-trivial statement is labeled per
   `CLASSIFICATION-LABELS.md` — Source-Derived Fact, Required, Inference,
   Proposed/Future, Open Question, or Stakeholder-Approved Decision. A statement does
   not change classification through repetition; it requires a recorded approval event.
3. **Current/Future separation.** Company future objectives (certifications, East
   Africa expansion, etc.) are never presented as current capability, anywhere,
   in any document.
4. **No silent correction of source discrepancies.** E.g., the "7+ Service Domains"
   claim vs. the 6 documented groupings stays open until the source itself is updated
   — never quietly "fixed" by a document author.
5. **Bilingual parity.** Any content chapter or artifact claiming completeness must
   address both en-US and am-ET, not just English with a translation TODO.
6. **Business-language test.** Before publishing any sentence: "Could this create a
   false business impression if copied into a live website, contract, or procurement
   document?" If yes — rewrite, qualify, source, or remove it.
7. **Promotional language is not this project's voice.** Quote the company's own
   promotional language (e.g., "leading" in their Vision statement) only when
   explicitly attributed as a company self-statement. Never adopt it as narration.
